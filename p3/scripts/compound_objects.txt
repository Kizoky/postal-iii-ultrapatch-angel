//While not completely documented, heres some stuff we know about compound props
//They're basically a single entity that "constructs" an object in a map out of physics props
//The first value (tv_02, Entrance, watercooler_01) is what you use in Hammer to say what object you want to construct
//The "body" is the prop used as the base
//The "door" or "screen" are additional props and their origin relative to the "body" or compound prop entity
//The "constraints" isn't fully understood and seems to handle how props are connected
//Additional parameters can be used for a few effects like "lock", "sleep", "class, "disableshadows", and "overridescript"
//"lock" isn't very well understood. It does something odd with welding and constraints.
//"sleep" sets the sleep flag on a physics prop. This will disable the prop from being able to move until a physics interaction "wakes it up"
//"class" seems to be exclusively used to define if a prop is meant to be placed as a static prop in a map. An example of this is "Boss_set_01e" which is used in city hall. Similar to p3_prop_tree, where the "model" gets turned into a static prop and placed, the model set to be static class will be turned into a static prop and placed in the map.
//"disableshadows" is self-explanatory. seems to disable shadows and is usually used on cabinet doors it looks like.
//"Overridescript" seems to only be used to change the mass of a selected prop. Might have other uses but hasn't been tested.
//Ultrapatch and UP+Angel specifically add a parameter called "motion" that can be used to disable motion of a prop. Used on "saguaro_01" to prevent the cacti from "running away" while retaining their breakability.
//Also important to note is that this file+entity is tempermental. If any MDL file in any object is missing, every object after it will become invalid and crash the game upon trying to be loaded.
